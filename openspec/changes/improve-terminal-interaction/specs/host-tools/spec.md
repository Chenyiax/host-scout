# Spec Delta

## Purpose

定义主机命令在交互式终端中可解释、可确认、可回看的信息边界，让用户知道模型为何提出命令、实际将运行什么，以及该调用最终是否访问了主机。

## ADDED Requirements

### Requirement: 可选命令用途说明

`run_command` SHALL 接受可选的 `purpose` 字符串，作为模型提供的命令用途说明；旧的仅含 `argv` 调用 SHALL 继续有效。非空 `purpose` SHALL 为单行且不超过 240 个 Unicode 字符，控制字符或超限 SHALL 在请求授权及访问主机前作为参数错误处理。该说明不得改变 argv 或执行权限。

#### Scenario: 模型提供用途

- **WHEN** 模型调用包含有效 `purpose` 和 `argv`
- **THEN** 授权提示分别展示标明为模型说明的用途与完整 argv，并说明命令输出将发送给模型

#### Scenario: 旧参数格式

- **WHEN** 模型调用只包含合法 `argv` 而未提供 `purpose`
- **THEN** 命令仍可进入逐次授权，提示明确标记未提供用途说明，完整 argv 仍可核对

#### Scenario: 用途参数无效

- **WHEN** `purpose` 包含换行、终端控制字符或超过长度限制
- **THEN** 调用返回参数错误，不请求授权、不启动进程，错误结果可被记录并反馈模型

### Requirement: 授权依据为完整命令

终端命令审批 SHALL 保持默认拒绝和每次调用单独授权。授权提示 SHALL 展示完整、经过安全转义的 argv；模型提供的用途仅供理解，不代表命令安全或已执行。拒绝、取消或输入 EOF 后 SHALL 明确记录未执行，旧授权输入不得转移到下一次调用。

#### Scenario: 用户核对后拒绝

- **WHEN** 用途说明看似无害，但用户查看 argv 后输入 `n` 或空行
- **THEN** 命令不执行，结果与终端展示均为拒绝/未执行，不产生主机观察

#### Scenario: 同一轮多条命令

- **WHEN** 一轮中模型先后提出两条命令，第一条获准
- **THEN** 第二条仍展示自己的用途与完整 argv 并独立等待授权

### Requirement: 用途与真实结果可回看

每个命令调用的内存记录 SHALL 保存调用 ID、开始和终结时间、真实状态及原有有界结果；参数可解析时还 SHALL 保存适用的模型用途说明与精确 argv。`/evidence <id>` SHALL 用可读字段展示这些内容；未执行调用不得显示执行耗时、退出码 0 或主机输出。记录 ID 与模型续接中的工具结果关联方式保持不变。

#### Scenario: 执行后模型失败

- **WHEN** 命令成功完成，但后续模型请求失败
- **THEN** 用户仍可通过记录 ID 查看用途、argv、执行状态、真实退出码及已保留输出

#### Scenario: 未执行记录

- **WHEN** 命令因拒绝、步骤上限或参数错误未启动
- **THEN** `/evidence <id>` 明确显示未执行原因，不把用途说明当作已验证的主机事实
