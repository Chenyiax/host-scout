# Design

## Context

参见 [proposal.md](proposal.md) 的动机。当前 `agent.Session` 已同步发出轮次、文本、工具和审批事件；CLI 仅选择性打印 `TextDelta`、`ToolProposed`、`ToolStarted` 和 `ToolFinished`。`terminalApprover` 单独输出确认提示，`inputReader` 在 raw mode 中逐字节回显，只处理输入、退格、Ctrl+C 和 EOF。命令参数只有 `argv`，记录含结果与时间，但没有可回看的原始调用说明。v1 的取消、逐次授权、管道逐行归属和 Linux 进程收尾均已验收，应保持这些边界。

## Goals / Non-Goals

**Goals:**

- 让终端呈现和真实事件状态一一对应，命令的“提出、待批准、已执行、未执行”容易区分。
- 在不改变模型/命令执行闭环的前提下改善输入和回看体验。
- 保持普通文本输出可用于管道和重定向；新增调用说明不削弱逐次授权。

**Non-Goals:**

- 不建立通用 TUI 框架、后台执行会话或执行中消息队列。
- 不从命令字符串推断安全等级，也不根据模型的用途说明自动批准。
- 不在本次引入持久化、token 预算或上下文压缩。

## Decisions

### 1. 在 CLI 建立单一事件呈现器

新增会话级呈现器消费现有 `agent.Event`，持有当前轮次和各 CallID 的显示状态；`terminalApprover` 继续负责实际 `y/N` 输入，但由同一呈现器负责审批信息布局，避免重复打印 `Proposed`、`Starting` 等日志。文本增量仍即时写出；状态行与文本边界由呈现器串行处理，`TurnFinished` 只打印一次结论，具体错误由现有错误分类生成对应恢复提示。等待模型时使用“等待模型响应”这类事实性文字，不假装知道内部推理进度。

曾考虑另建异步事件总线或完整 TUI；现有同步 Hook 已足以覆盖本次流程，引入第二套状态源会增加取消与输出顺序风险。

### 2. 终端能力由输入和输出分别判定

仅当输入与输出都连接终端时启用行内编辑和必要的光标控制。任何输出重定向或管道模式均采用静态纯文本；不输出 ANSI 颜色、动画或光标转义。状态以追加的短行呈现，即使终端不支持原位刷新也能阅读。原始模型文本和工具输出在展示层转义 ESC、回车及其他非换行/制表控制字符；流式展示缓冲不完整 UTF-8 字符并安全处理控制字节，不能因 SSE 分片边界漏出控制字符或破坏中文。记录和回传模型的有界原始结果不因显示转义而改变。

曾考虑默认启用彩色进度动画；它对重定向、Windows 终端和自动化测试的兼容负担较高，本次先交付清晰的文本层级。

### 3. 在现有输入所有者内扩充行编辑

保留唯一输入消费者和可取消 `ReadLine`。就绪态编辑器维护文本、光标和临时历史位置；审批态复用编辑键，但禁用历史检索且不存入历史。支持常见方向键、Home/End、Delete/Backspace；按 Unicode 字符边界编辑并按显示列宽重绘。对于组合字符和宽字符，采用经过验证的小型 Unicode 分段/宽度库或等效实现，并在 Linux PTY 与 Windows 终端验证。历史只保存已提交的普通问题，限制条目数与总字节数，`/clear` 清空；未提交草稿在历史浏览后可恢复。

曾考虑直接替换为通用 readline 库；其输入 goroutine、raw mode 和取消语义可能与已验收的审批/EOF 归属冲突，因此先在当前输入所有权模型内扩充。

### 4. 用途说明保留为模型数据

`run_command` 参数增加可选 `purpose`，严格限制长度并拒绝控制字符；未提供时使用明确的缺省说明，旧参数保持有效。`policy.CommandRequest` 把用途与 argv 一起传给审批呈现器，但授权决策仍只针对当次精确 argv。记录在现有内存证据中保存有界调用参数；CLI 仅解析 `run_command` 的已知字段用于 `/evidence`，未知或无效参数安全显示错误，不要求 Agent 理解具体工具的业务字段。记录 ID 和回传模型的结果格式不变。

曾考虑强制模型必须提供用途或从 argv 自动生成用途；前者会破坏旧调用，后者会让不可靠的猜测看起来像事实。界面始终标注“模型说明”，完整 argv 仍是用户批准的依据。

### 5. 预览与详情分层

命令终结时展示状态、适用的执行耗时/退出码、记录 ID，以及至多约 1 KiB、8 行的安全转义输出预览。拒绝、跳过、参数错误不显示虚构输出或耗时。`/evidence <id>` 改为按字段展示用途、argv、时间、状态、退出码和原有最多 32 KiB 的结果；必要时说明预览被省略或命令未执行。格式化只改变用户可见输出，不改变工具结果、历史提交或模型续接。

曾考虑默认展开完整命令输出；长输出会淹没对话，且可能包含业务数据，短预览加显式详情更适合终端。

## Risks / Trade-offs

- [行编辑重绘在不同终端的字符宽度可能不一致] → 用真实 PTY 和 Windows 终端覆盖中文、宽字符、组合字符、删除及窗口边界；对输入或输出并非终端的情况使用纯文本路径，不输出破损控制序列。
- [模型用途说明可能不准确] → 始终标明来源，单独展示完整 argv，坚持默认拒绝和逐次确认。
- [自动预览可能暴露命令输出中的敏感信息] → 预览有界且仅在用户批准执行后显示；对控制字符转义，不增加文件持久化或额外远端发送。
- [记录调用参数增加内存占用] → 为展示副本设置独立上限；历史与已有结果仍遵守原有边界，`/clear` 一并清除。
- [改动输出格式可能影响依赖旧文案的脚本] → 管道保持纯文本与输入顺序，在 README 说明显示文案不是机器接口，保留状态码、CallID 和记录 ID 等可识别信息。

## Migration Plan

1. 先补命令用途字段及记录展示数据，保持旧 `argv` 调用通过；随后接入呈现器和帮助/错误文案，最后增加行编辑与历史。
2. 用本地 fake Client/Tool 覆盖事件与非 TTY 输出，再跑 Linux PTY 的授权、取消、EOF、中文编辑和历史场景；Windows 验证真实终端输入，运行 `go test ./...` 与 `go vet ./...`。
3. 更新 README 和交互验收记录。v1 变更尚未归档；归档或同步规格时先处理 v1，再处理本变更，避免主规格只保留本次新增要求。回退代码版本即可恢复旧呈现，内存会话无格式迁移。
