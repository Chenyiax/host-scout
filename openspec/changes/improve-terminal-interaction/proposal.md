# Proposal

## Why

Host Scout 已有流式对话、命令审批、取消和执行记录，但终端主要输出原始事件与调用 ID。用户在模型等待、授权和工具结束时难以快速判断当前状态、命令用途和下一步操作；原始输入组件也缺少常用的编辑与历史能力。

## What Changes

- 将一轮对话呈现为明确的等待模型、等待授权、执行命令和完成/中止状态；只展示可观察到的状态，不推测模型内部进度或虚构百分比。
- 将工具事件合并为可读的命令区块：在授权前展示完整 argv、模型提供的简短用途和输出去向，在结束时展示真实状态、耗时、记录 ID 与有界结果摘要；保留 `/evidence` 查询详情。
- 改善交互式终端输入：支持光标移动、常用编辑键和本会话普通提问历史；审批回答及密钥不进入历史。明确运行期间的输入提示和 Ctrl+C 行为。
- 统一帮助、错误和恢复提示，使用户能从输出直接知道能做什么；管道输入保持纯文本、无终端控制序列，并保留既有逐行归属。
- `run_command` 增加可选、长度受限的用途说明参数；旧的仅含 `argv` 调用仍有效。用途是模型说明，不能替代用户核对完整命令和逐次授权。
- 本次不引入完整 TUI、执行中消息队列、后台命令、会话持久化、自动上下文压缩、风险分级或自动放行。它们可在本次交互验收后单独评估。

## Capabilities

### New Capabilities

- `terminal-session`：沿用 v1 变更中的能力路径，补充终端状态、输出、输入编辑、帮助和错误恢复的可观察契约。当前仓库尚未将 v1 delta 同步到主规格。
- `host-tools`：沿用 v1 变更中的能力路径，补充命令用途参数及授权/结果展示所需的记录语义。

### Modified Capabilities

无；当前 `openspec/specs/` 没有主规格。此变更沿用已有 delta 的能力名称，新增要求不重写 v1 的执行与授权边界。

## Impact

- 主要涉及 `internal/cli` 的事件呈现、授权提示和交互式输入，少量涉及 `internal/tools/command` 的参数定义及 `internal/agent` 向终端提供的事件数据。
- 更新终端和管道模式测试、Linux PTY 验收、README 的交互说明；不改变 Responses 传输协议、命令执行预算和平台清理保证。
