## 1. 通用模型与公开工具契约

- [x] 1.1 在 `internal/model` 补齐通用助手消息和工具调用 item、Provider 载荷归属及错误类别；验证没有 Responses 载荷的 item 能表达完整文本和工具往返，且模型抽象不导入具体 Provider。
- [x] 1.2 在 `internal/agent` 接入可注入指令和窄 Client 依赖；用 fake Client 完成连续两轮聊天和一次工具调用，检查实际请求中的历史、指令及工具定义，确保无需 Responses JSON。
- [x] 1.3 为新增模型字段、载荷归属和回调约定补充包注释，并检查注释与 fake Client 的契约测试一致，明确本期不支持会话中跨 Provider 热切换。
- [x] 1.4 在公开 pkg/tool 提供独立 Definition、Status、Result、Tool 与启动时 Registry，Run 返回统一结果并接受 context；迁移内部工具定义/结果依赖和开始通知，拒绝空、无效或重名定义，检查公开包不导入 internal 或 Responses。
- [x] 1.5 用独立临时 Go 模块导入公开工具包实现/注册 fake 工具，并在原 Agent 中验证注入、定义发现、取消和工具往返；补充包注释与最小扩展示例，不公开完整 Agent SDK。

## 2. Responses 适配器

- [x] 2.1 更新 `internal/providers/openairesponse` 的通用 item 编解码，原始 output 载荷只续传一次；扩展现有 HTTP 往返测试，验证 reasoning 加密载荷、message 字段、多个调用顺序和 `call_id` 保真。
- [x] 2.2 补齐 SSE 事件解析边界及累计 8 MiB 上限，完成事件后及时返回；用 LF/CRLF、多行 data、注释、未知事件、缺少完成事件、非法 JSON 和超限 fixtures 验证，不等待额外 `[DONE]` 或 EOF。
- [x] 2.3 在已有错误分类上增加通用 context_limit，并有界读取 HTTP/SSE 的明确错误码；本地 fixtures 验证 context_length_exceeded 可区分、普通 HTTP 400 与输出限制不误判、错误体和测试密钥不回显，部分响应永不执行；更新包说明。
- [x] 2.4 固定 v1 Responses 请求行为并记录兼容边界；断言路径、认证和 `stream/store/parallel_tool_calls` 参数，验证非 SSE 端点明确失败，包说明不声称支持其他 API。
- [x] 2.5 在一次 Client.Create 内实现最多两次额外 HTTP 尝试、同输入快照与可取消退避；用本地服务/可控时钟测试瞬时失败后成功、第三次失败终止、允许的 HTTP 状态、永久错误不重试及 Retry-After 不被提前截短，超过 30 秒放弃，整个调用不因重试重置总超时。
- [x] 2.6 测试收到任意 SSE data（包括 response.created/工具片段）后断流不重试、失败尝试不提交、重试等待取消立即结束；更新 Provider 注释，明确只重试当前模型请求、不执行工具且不保证远端计算 exactly-once。
- [x] 2.7 用请求断言验证 v1 不发起压缩/摘要/Conversations 调用，不启用自动压缩或自动截断；明确全量有效历史续传和自定义端点的最低兼容边界。

## 3. 工具结果与最小执行契约

- [x] 3.1 在现有工具模块增加统一结果状态、稳定错误码和实际执行开始 Hook；用 fake Tool/Approver 验证拒绝、参数错误和取消前的调用没有执行开始事件，成功/非零退出有明确终结状态。
- [x] 3.2 更新 command 结果的可空退出码、超时/取消判定和输出截断标识，保留 argv 校验及环境白名单；扩展 command 测试覆盖非零退出、无退出码的启动失败、32 KiB 输出和密钥环境隔离。
- [x] 3.3 通过 Linux 专属实现加入命令进程组终止，保留非 Linux 开发模式；在 Linux 上用受控父子进程测试验证超时或取消会清理同组子进程，本地取消等待不超过 2 秒，Windows/macOS 分支可编译。
- [x] 3.4 标准 CLI 所有平台仅注册 run_command，去掉 /proc 默认工具和“先用只读内置工具”的指令/提示；通过启动、/tools 和模型请求测试断言工具集合一致且仅一个，未知旧工具返回 unknown_tool，不自动替换成命令；更新 command 描述与平台边界说明。
- [x] 3.5 在 Linux 用显式 shell 启动同组子进程，测试取消/超时会终止 shell 与普通后代、清理等待不超过 2 秒且失败不伪报清理成功；保留 Windows/macOS 直接进程保证并更新工具包说明。
- [x] 3.6 在 command 内建立私有、一次性且幂等的执行所有权，区分直接进程退出与输出 EOF；Linux 真实进程测试覆盖主进程正常/非零退出后仍有同组后代、后代持有管道、重复取消、连续调用资源不累积及不影响其他进程组，启动失败不误杀；收尾总计最多 2 秒，其中管道等待最多 1 秒，不新增 PTY、后台会话或公开进程管理器。
- [x] 3.7 通过可注入的私有平台操作测试终止失败、直接进程未回收和清理等待耗尽，统一返回 failed/cleanup_failed 并保留 termination_reason、已取得输出和真实退出码；验证外层取消/超时不覆盖清理错误、已取消 context 不跳过清理，更新平台边界说明，不以测试桩代替 Linux 真实取消验收。

## 4. Agent 轮次与历史

- [x] 4.1 引入轮次开始/终结、工具提出/开始/终结和审批事件，接入命令审批包装器；断言成功、拒绝、失败、取消、超限时的事件顺序及终结唯一性，非命令工具没有审批事件。
- [x] 4.2 实现单会话忙碌保护及记录快照，清空限定于就绪态；测试并发 Ask 返回 busy 不修改历史，读取返回值不能修改内部记录，Clear 后不携带旧历史或续传载荷。
- [x] 4.3 实现接受用户输入、完整有效响应及每项工具结果的增量历史提交；测试首次模型失败仍保留用户输入、工具后模型失败保留结果、未完成文本不作为完整回答续传。
- [x] 4.4 在任何工具执行前验证本批名称和 CallID，拒绝批内重复与历史冲突；测试坏批次不产生部分执行、不进入历史，未知工具和参数错误则生成可反馈模型的失败结果。
- [x] 4.5 将上限改为可选非负值，保留最后允许响应的跳过/配对规则；测试 0 不限、负数拒绝、max_steps=1 不执行最后批工具、最后一步文本成功、逐 Turn 计数、HTTP 重试只算一次模型接口调用；更新护栏语义说明。
- [x] 4.6 实现默认持续的简单顺序循环；fake Client 连续九次工具往返后第十次回答仍属同一 Turn，覆盖文本+工具不中止、拒绝/失败可反馈、澄清结束后下一轮带历史、空响应明确失败；不引入引导或 hooks。
- [x] 4.7 更新 agent 包说明与边界：内核推进 Turn、维护历史、调度工具和传递取消；不处理 HTTP 细节、终端读输入、固定诊断流程或复杂规划；核对说明与本组测试一致。
- [x] 4.8 集成测试同一取消信号贯穿模型/退避/授权/命令，命令收尾返回成功或明确失败并完成调用配对之后才发 TurnFinished/解除 busy；cleanup_failed 以失败终止本轮，保留原始原因并为剩余调用补 skipped/cleanup_failed，不被 ctx.Err 覆盖，取消或收尾失败后无总结请求或后续动作；后续模型重试和下一轮追问不重跑旧工具。
- [x] 4.9 测试工具完成后上下文超限明确失败、所有历史/结果保留、没有缩短输入重试、用户显式 Clear 后重新请求；更新错误与恢复说明，不实现压缩器或 token 预算。
