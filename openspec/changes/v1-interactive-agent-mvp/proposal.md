# Proposal

## Why

Host Scout 已有可运行的多轮聊天和工具闭环，但默认有限步骤会过早打断任务，内置诊断工具也扩大了第一期边界。v1 收敛为参考 Codex 运行语义的轻量交互式 CLI：默认持续推进一个 Turn，支持基本提问、逐次命令授权和贯穿执行链路的取消。

## What Changes

- 明确 v1 交付范围：本地终端、纯文本、多轮会话、流式回答、顺序工具调用、逐次命令确认和内存内记录。
- 第一阶段仅实现 Responses API 的 HTTP/SSE 适配器；自定义 `base-url` 仍须提供同样的协议，不自动降级到其他 API。
- 保留窄的 `model.Client` 抽象，补齐通用消息与工具结果的表达；Provider 特有续传数据作为不透明载荷，由适配器管理。
- **BREAKING**：Turn 默认不设模型调用次数上限；完成回答或澄清问题后结束，命令结果回传后继续。将默认 8 次、范围 1..100 改为可选非负上限，配置文件中 `max_steps` 缺省或为 0 表示不限。
- **BREAKING**：唯一内置工具为 `run_command`，不再注册 `inspect_system`、`list_processes`；公开最小工具定义、执行和结果契约，允许启动时注入扩展工具，不建立动态插件系统。
- 明确取消、错误、显式上限和历史提交规则；取消贯穿模型请求、重试等待、授权和 shell 执行，清理受管理进程后才结束 Turn，已完成结果不丢失、不自动重跑。
- 命令保持一次性同步执行，每次调用拥有进程与 I/O；Linux 正常退出、超时或取消均收尾本次进程组，有界等待并显式报告 cleanup_failed。清理失败保留原始原因与已完成结果，停止本轮后续动作，不伪报全部进程已终止。
- 保留轻量轮次/工具事件与现有本地 CLI 命令，不引入专门的澄清工具或方向引导机制。
- 新增显式 TOML 配置文件入口，保留命令行、模型/端点环境变量和隐藏凭据输入；命令超时、输出上限与环境白名单保持不变。
- 模型当前请求内允许有限的瞬时网络/HTTP 重试，不重启 Turn、不重跑工具；上下文超限明确停止，不静默截断历史，不调用压缩接口。
- 为现有与新增行为补充确定性的测试和 Linux 终端验收步骤。

v1 采用逐轮交互：用户可在本轮结束或取消后继续提问。复杂方向引导、planner、Stop hooks、执行中消息注入、消息队列、完整 TUI、并行工具、多 Agent、其他 API 实现、风险分级、完整脱敏、持久化、诊断包下载、独立报告、token/费用预算、上下文压缩/摘要/自动裁剪、后台命令会话、PTY、stdin 续写、进程池、Web 和远程控制均不在本期范围。内核推进模型与工具闭环，不硬编码独立诊断流程。

## Capabilities

### New Capabilities

- `agent-runtime`：默认持续运行、普通澄清、历史完整性、可选调用上限、取消恢复和轻量事件。
- `terminal-session`：配置与凭据输入、逐轮终端交互、本地命令、授权输入和取消后的继续使用。
- `model-provider`：Provider 独立接口、Responses HTTP/SSE、工具续传、有界重试和上下文超限语义。
- `host-tools`：单一内置命令工具、公开扩展契约、逐次审批、进程清理和内存内调用记录。

### Modified Capabilities

无。项目尚无主规格；本变更首次定义 v1 行为契约，其中包含已经存在、需要保持的行为。

## Impact

- 涉及现有 agent、model、Responses、CLI、config、tools 和 policy 模块，以及新的公开 `pkg/tool` 包；保留 Go 工程及入口，不发布完整 Agent SDK。
- 保留现有启动参数和模型/端点环境变量；新增 `--config`，`--max-steps` 的默认值与有效范围改变，不再保证旧的默认截断行为。
- Linux 为正式执行平台，Windows/macOS 保留聊天和命令工具的开发模式。
- TOML 可采用小型成熟解析依赖，不引入 Agent 框架；契约测试使用 fake Client/Tool 和本地 HTTP/SSE 服务，不依赖付费 API。
- 本次只产出规划文档；实现由后续 apply 工作流推进。草案中的设计选择和具体验收标准见 `design.md` 与四份 delta specs。
