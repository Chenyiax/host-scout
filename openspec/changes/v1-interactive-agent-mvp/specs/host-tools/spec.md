# Spec Delta

## Purpose

定义 v1 唯一内置命令工具的发现、参数、授权和结果行为，并提供可由后续工具实现的公开最小扩展契约。保证用户能够区分提议与实际执行，查看有界结果，在拒绝、超时或取消后继续使用会话，不引入固定诊断采集器或动态插件系统。

## ADDED Requirements

### Requirement: 单一内置且可发现的工具集合

v1 发行版 SHALL 在所有支持的平台仅内置并注册 `run_command`，不向模型声明 `inspect_system` 或 `list_processes`。发现列表 SHALL 与实际注册并发送给模型的工具集合一致，定义有效且名称唯一。主机观察 SHALL 由获授权命令完成，不需要专用诊断工具；v1 不下载、安装或动态加载插件。

#### Scenario: Linux 工具发现

- **WHEN** 用户在 Linux 启动会话并查看工具列表
- **THEN** 仅 run_command 的名称、描述和参数定义可被发现，模型收到同一工具集合

#### Scenario: 非 Linux 开发模式

- **WHEN** 用户在 Windows 或 macOS 启动会话
- **THEN** 工具集合仍仅含 run_command，终端说明平台进程清理保证，不提示缺少本期不交付的 /proc 工具

### Requirement: 公开最小工具扩展契约

项目 SHALL 提供可被其他 Go 模块导入的工具契约和启动时注册入口。工具 SHALL 提供名称、描述、JSON 参数 Schema，以及接受取消信号的执行方法，返回可序列化的统一状态、数据与错误信息；相关类型不得要求扩展方导入 internal 包或 Responses 类型。新增工具 SHALL 通过注入和注册接入，不修改 Agent 循环或 Provider。该扩展入口不改变发行版只内置一个工具的范围。

#### Scenario: 外部模块实现工具

- **WHEN** 独立 Go 测试模块仅导入公开工具包并实现一个 fake 工具
- **THEN** 实现可编译并经注册入口进入工具定义和执行分发，不引用内部模型类型或远程协议字段

#### Scenario: 扩展工具复用运行时

- **WHEN** 测试组装向会话注入符合契约的 fake 工具
- **THEN** 原有 Agent 可执行该工具并回传关联结果，历史和过程事件语义不变，无需新增内核分支

#### Scenario: 注册集合无效

- **WHEN** 启动组装尝试注册空实现、无效定义或重复名称
- **THEN** 注册失败且不请求模型，不允许后注册的工具静默覆盖已有实现

### Requirement: 参数在主机访问前校验

工具 SHALL 在访问主机或请求授权前严格校验 JSON 和参数，拒绝未知字段、多个 JSON 值及不满足工具约束的输入。未知工具不产生主机访问或审批。工具结果 SHALL 可序列化并区分成功、参数错误和执行错误。

#### Scenario: 非法命令参数

- **WHEN** 参数包含空 argv、超过 32 个参数、超过 4 KiB 的 argv 总字节数、控制字符、空可执行名或多余字段
- **THEN** 校验失败，不请求审批也不启动进程

#### Scenario: 未注册工具

- **WHEN** 模型提出未注册的 inspect_system 或其他工具调用
- **THEN** 返回 unknown_tool 结果，不访问主机、不请求授权、不自动转换为 shell 命令

### Requirement: 命令逐次授权

`run_command` SHALL 对每次合法调用请求一次明确审批，仅允许后才能启动精确 argv 对应的进程，不自动添加 shell，也不提升当前用户权限。拒绝或非交互式输入 SHALL 不执行命令；v1 不支持会话级永久放行或自动风险分类。

#### Scenario: 拒绝不执行

- **WHEN** 用户拒绝一个合法 argv
- **THEN** 没有对应进程被启动，结果标记为 denied 并反馈模型

#### Scenario: 多命令分别确认

- **WHEN** 同一模型响应提出两个命令且第一个得到允许
- **THEN** 第二个仍需独立确认，没有继承第一个的授权

### Requirement: 一次性命令与执行所有权

`run_command` SHALL 采用一次性同步执行：每次已启动调用独立拥有直接进程、受管理进程组及输入输出资源，命令终结时收尾后再返回。Linux 主进程正常或非零退出后，仍处于本次进程组的后代 SHALL 被终止，不作为后台服务保留。重复取消 SHALL 不产生重复结果或独立清理任务。v1 不提供后台执行、可续接执行会话 ID、PTY、stdin 续写或进程池。

#### Scenario: 正常退出后留下同组后代

- **WHEN** Linux 已批准 shell 启动同组后台子进程后以 0 退出
- **THEN** 终止残留同组后代并完成有界收尾后才返回成功；不把主进程退出或输出 EOF 单独当作整次调用清理成功

#### Scenario: 多次取消同一次执行

- **WHEN** 同一次命令在取消与收尾期间多次收到取消信号
- **THEN** 仅收尾该次调用拥有的资源并生成一个终结结果，不重复执行命令、不创建新的执行会话

#### Scenario: 无跨调用后台会话

- **WHEN** 一次命令完成或被取消
- **THEN** 工具仅返回最终状态和有界输出，不返回用于后续读写的后台执行句柄，不接受恢复该次执行的输入

### Requirement: 有界命令执行与状态

命令执行预算 SHALL 为 10 秒，收尾等待另受清理期限约束；合并 stdout/stderr 最多保留 32 KiB，并明确标记截断。结果 SHALL 区分 succeeded、failed、timed_out 和 cancelled，包含适用的真实退出码；未取得退出码用空值，不得用虚构的 0 表示超时或失败。子进程仅继承最小环境白名单，不继承模型凭据。

#### Scenario: 非零退出

- **WHEN** 一个已批准命令以非零状态退出
- **THEN** 返回 failed、真实退出码和有界输出，不报告执行成功

#### Scenario: 输出过大

- **WHEN** 命令输出超过 32 KiB
- **THEN** 保留内容不超过上限并设置 truncated，继续排空输出直到命令终结或超时

#### Scenario: 凭据环境隔离

- **WHEN** 父进程配置了 `HOST_SCOUT_API_KEY`、`OPENAI_API_KEY` 或其他非白名单环境变量
- **THEN** 命令子进程环境不包含这些变量

### Requirement: 取消与 Linux 子进程清理

命令执行和审批 SHALL 响应当前 Turn 取消。Linux 命令超时或取消时 SHALL 强制终止命令（包括显式启动的 shell）及仍处于执行进程组中的后代。正常退出、超时或取消触发收尾后，本地清理等待 SHALL 在 2 秒内结束，成功或失败均有明确结果；收尾结果返回前不得结束 Turn 或启动下一项。Windows/macOS 开发模式 SHALL 至少清理直接进程并说明差异。v1 不承诺回滚副作用、终止主动脱离进程组的进程或操作系统异常下的强制回收成功。

#### Scenario: Linux 子进程未自行退出

- **WHEN** 已批准命令启动同进程组子进程后被取消
- **THEN** 父子进程均被终止，本地等待在 2 秒内结束，结果标记 cancelled

#### Scenario: 命令超时

- **WHEN** Linux 命令超过 10 秒仍运行
- **THEN** 清理该执行进程组并返回 timed_out，不继续等待子进程持有的输出管道

#### Scenario: 显式 shell 的子进程清理

- **WHEN** 用户批准的 argv 显式启动 Linux shell，shell 启动同组子进程后用户取消
- **THEN** shell 和子进程均终止，等待回收与输出管道处理有界，结果为 cancelled，不留下普通同组进程继续运行

#### Scenario: 开发平台取消

- **WHEN** 用户在 Windows 或 macOS 取消已启动命令
- **THEN** 直接进程被取消并结束本地等待，不将这一行为描述为已验证的完整进程树清理

#### Scenario: 后代持有输出管道

- **WHEN** Linux 直接进程已退出，但同组后代仍持有 stdout 或 stderr
- **THEN** 终止受管理后代并有界处理管道，不无限等待 EOF；不能在 2 秒内完成收尾时返回清理失败，不把截断输出或关闭管道当作后代已终止的证据

### Requirement: 清理失败与终止原因

工具 SHALL 保留成功、非零退出、取消或超时的原始终止原因，并独立判断平台保证范围内的清理是否成功。终止请求失败、直接进程未回收或清理等待耗尽 SHALL 返回 failed/cleanup_failed 和安全可展示的残留风险，不被外层取消或工具超时覆盖。已取得的输出与真实退出码 SHALL 保留，但不作为清理成功依据；发出信号不等于完成回收。

#### Scenario: 取消时终止请求失败

- **WHEN** 用户取消命令，但平台终止操作返回错误
- **THEN** 返回 failed/cleanup_failed 并保留原始取消原因，不只报告 cancelled，不声称命令及其子进程均已结束

#### Scenario: 成功退出后清理失败

- **WHEN** 主进程以 0 退出，但受管理资源未能在收尾期限内清理
- **THEN** 返回 failed/cleanup_failed，保留已取得的输出和退出事实，不报告整次调用 succeeded

#### Scenario: 超时收尾未完成

- **WHEN** 命令达到 10 秒执行超时，随后未能在 2 秒清理等待内完成回收
- **THEN** 有界结束本地等待，返回 failed/cleanup_failed 和原始超时原因，不无限阻塞或伪报 timed_out 且已清理成功

### Requirement: 内存内可回看记录

工具处理 SHALL 为每个已接受调用保留会话内唯一记录 ID、调用标识、工具、时间、终结状态和有界结果，通过 `/evidence` 可查询，并在回传模型时携带记录引用。拒绝、错误、取消和未执行的记录不得表示为成功观察；v1 不要求磁盘持久化或报告系统。

#### Scenario: 成功结果可回看

- **WHEN** 一个工具执行成功且模型之后出错
- **THEN** 用户仍能通过记录 ID 查看已完成结果，且后续对话可引用该结果

#### Scenario: 未执行记录可区分

- **WHEN** 命令因用户拒绝或步骤上限而未执行
- **THEN** 记录明确标识 denied 或 skipped 及原因，不含虚构的主机观察或成功退出码

#### Scenario: 清空与退出

- **WHEN** 用户清空或退出会话
- **THEN** 当前内存记录被清除，不自动写入诊断文件或远程存储
