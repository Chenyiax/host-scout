# Spec Delta

## Purpose

定义本地终端作为 v1 主要入口的基本使用契约，让用户能够配置模型、持续提问、查看工具结果和确认命令。通过明确的输入归属、取消与退出行为，支持轻量的逐轮交互而无需完整终端界面或后台任务系统。

## ADDED Requirements

### Requirement: 模型配置与启动

终端 SHALL 接受 `--config`、`--model`、`--base-url`、`--max-steps` 和 `--allow-insecure-http`。模型/端点优先级 SHALL 为显式命令行、对应环境变量、配置文件、默认值；默认端点为 `https://api.openai.com/v1`。步骤上限默认不限，允许 0 或可表示的正整数，不再限制为 1..100。缺少模型、无效 URL 或步骤上限 SHALL 在发起请求前报错。

#### Scenario: 参数覆盖环境变量

- **WHEN** 环境变量提供模型和端点，用户同时传入不同的 `--model` 与 `--base-url`
- **THEN** 会话使用命令行指定值，启动状态显示实际模型、端点、平台和可用工具

#### Scenario: 非安全远程端点

- **WHEN** 用户指定非回环 HTTP 端点且没有传入 `--allow-insecure-http`
- **THEN** 启动失败且不发送凭据或诊断数据；回环 HTTP 可用，远程 HTTP 仅在显式启用后可用

#### Scenario: URL 含凭据或查询片段

- **WHEN** 端点包含 URL 用户凭据、查询参数或 fragment
- **THEN** 启动失败并说明配置无效

### Requirement: 显式配置文件与可选护栏

终端 SHALL 仅在提供非空 `--config <path>` 时读取 TOML 配置，接受顶层 `model`、`base_url`、`max_steps` 和 `allow_insecure_http`，拒绝未知字段和错误类型。`max_steps` 缺省或为 0 SHALL 表示不限，正整数为调用上限，显式 `--max-steps`（包括 0）优先。文件不存在、不可读、语法错误、负数或整数溢出 SHALL 在请求前报错，不静默回退。配置不得接受 API Key，不自动搜索或创建配置文件。

#### Scenario: 未配置限制

- **WHEN** 没有配置文件或 max_steps 字段缺省，且没有显式 --max-steps
- **THEN** 启动状态显示请求次数不限，模型和端点可继续使用环境变量或命令行配置

#### Scenario: 文件设置上限

- **WHEN** 配置文件包含 max_steps = 12，命令行没有提供步骤上限
- **THEN** 每个 Turn 的模型调用最多 12 次，启动状态与 /status 均显示 12

#### Scenario: 显式解除文件限制

- **WHEN** 文件配置 max_steps = 12，用户显式传入 --max-steps 0
- **THEN** 实际上限为不限，而不是将 0 当作未提供参数后仍使用 12

#### Scenario: 环境变量覆盖文件模型

- **WHEN** 文件配置 model/base_url，环境变量提供其他模型和端点，命令行未显式覆盖
- **THEN** 使用环境变量值，同时仍应用文件中的 max_steps

#### Scenario: 配置无效

- **WHEN** 显式文件缺失、TOML 无效、max_steps 为负数/非整数/溢出，或含未知 api_key 字段
- **THEN** 启动失败且不发起模型请求、不输出字段值，不以默认不限掩盖错误

#### Scenario: 大于旧上限的合法限制

- **WHEN** 文件配置 max_steps = 150
- **THEN** 启动接受该正整数，不保留旧的 100 次人为上界

### Requirement: 凭据输入与隔离

终端 SHALL 从 `HOST_SCOUT_API_KEY` 读取凭据，缺失时仅在交互式终端隐藏输入读取；非终端输入缺失凭据时 SHALL 启动失败。不得提供 API Key 命令行参数、回显或主动将该密钥加入对话、工具记录和子进程环境；错误展示不得输出已配置密钥。

#### Scenario: 隐藏输入

- **WHEN** 交互式终端未配置凭据
- **THEN** 提示输入 API Key，输入字符不可见，空凭据不启动会话

#### Scenario: 非终端输入未提供密钥

- **WHEN** 标准输入为管道且没有 `HOST_SCOUT_API_KEY`
- **THEN** 返回需要环境变量凭据的错误，不从普通聊天输入中读取密钥

### Requirement: 逐轮对话

终端 SHALL 将就绪状态下的非空普通输入作为新用户消息，持续显示模型文本增量。本轮终结后恢复提示符，允许用户追问、补充、纠正和调整目标。空白输入不发起模型请求；v1 不提供执行中普通消息的即时注入或排队承诺。

#### Scenario: 连续提问和澄清

- **WHEN** 用户在回答后输入“是 PID 23，先不要采样”
- **THEN** 该信息进入下一轮对话，已有历史保留；不要求用户重新启动进程

#### Scenario: 回答模型的澄清问题

- **WHEN** 模型提出普通澄清问题且当前 Turn 已结束，用户提交回答
- **THEN** 回答作为下一轮用户消息，携带历史，不需要填写表单、选择引导方向或调用专门提问工具

#### Scenario: 空白输入

- **WHEN** 用户在提示符输入空格或空行
- **THEN** 终端重新等待输入，不计入轮次或步骤

### Requirement: 本地会话命令

终端 SHALL 支持 `/help`、`/status`、`/tools`、`/evidence [id]`、`/clear`、`/exit` 和 `/quit`，并在本地处理而不发送给模型。未知本地命令 SHALL 给出帮助提示。v1 不要求 `/plan`、`/permissions`、`/report`、`/export` 或 `/cancel`。

#### Scenario: 查看状态与工具

- **WHEN** 用户输入 `/status` 或 `/tools`
- **THEN** 分别显示实际模型、端点、正整数上限或“不限”及记录数量，或唯一内置 run_command 的定义，不发起模型请求

#### Scenario: 查看记录与清空

- **WHEN** 用户输入 `/evidence <id>` 后再输入 `/clear`
- **THEN** 先显示该记录的工具、调用关联、状态、时间与有界输出，再清空当前历史和记录；不存在的 ID 返回未找到

### Requirement: 命令授权输入归属

终端 SHALL 在命令执行前显示完整 argv 和输出会发送给模型的提示。只有当前有效授权提示下的 `y`（大小写不敏感、忽略两端空白）表示允许一次；其他输入默认拒绝，且不作为聊天消息。取消或 EOF SHALL 解除授权等待，失效授权不得用于后续调用。

#### Scenario: 允许一次

- **WHEN** 用户在授权提示输入 `y`
- **THEN** 只授权该次显示的命令，下一次命令仍须再次确认

#### Scenario: 非确认内容

- **WHEN** 用户在授权提示输入空行、`n` 或其他文字
- **THEN** 当前命令不执行，该输入不发送给模型，终端提示这是拒绝并允许在本轮结束后重新输入聊天内容

### Requirement: 取消和退出

终端 SHALL 在模型请求、重试等待、授权或命令执行期间响应 Ctrl+C，将取消传递给当前 Turn。命令执行时 SHALL 等待平台返回清理成功或明确失败的收尾结果并收到轮次终结后恢复提示符，不仅取消界面显示。就绪态 Ctrl+C SHALL 清除未提交输入而不退出。`/exit`、`/quit` 或 EOF SHALL 正常关闭会话；EOF 在运行或授权中 SHALL 取消当前工作，不再执行命令或请求模型。

#### Scenario: 授权等待时取消

- **WHEN** 命令确认提示正在等待输入时用户按 Ctrl+C
- **THEN** 该命令不执行，本轮显示取消，用户无需再输入一行即可返回提示符并继续提问

#### Scenario: 就绪时取消输入

- **WHEN** 用户在提示符输入未提交文字并按 Ctrl+C
- **THEN** 该文字不提交，进程仍运行并显示新的提示符

#### Scenario: 授权等待时关闭输入

- **WHEN** 授权输入遇到 EOF
- **THEN** 当前命令不执行，本轮停止且会话退出，没有后续模型请求

#### Scenario: shell 执行期间取消

- **WHEN** Linux 已批准 shell 及同组子进程运行时用户按 Ctrl+C
- **THEN** shell 和子进程被清理，工具与 Turn 显示取消，不显示成功，不发起总结请求，清理完成后才能提交下一轮输入

#### Scenario: 重试等待期间取消

- **WHEN** 模型请求正在退避等待重试时用户按 Ctrl+C
- **THEN** 等待被打断，轮次取消并恢复提示符，不要求用户等待退避结束或再输入换行

#### Scenario: 执行期间关闭输入

- **WHEN** 当前 Turn 正在模型请求或命令执行中，输入源报告 EOF
- **THEN** 当前工作被取消，命令按平台契约清理，之后关闭会话且没有后续请求或工具启动

### Requirement: 过程与失败展示

终端 SHALL 展示工具提出、等待确认、实际执行与终结状态，以及本轮成功、取消、失败或达到限制的结果。模型失败或步骤超限 SHALL 返回可继续使用的提示符；已流式显示的文本不得因收到最终文本而重复打印。命令 cleanup_failed SHALL 显示明确失败、原始终止原因和可能仍有残留进程的提示，不只显示取消或超时，不声称已完成清理。

#### Scenario: 模型出错后继续使用

- **WHEN** 一轮模型请求发生网络或协议错误
- **THEN** 显示有界且不含已配置 API Key 的错误信息，恢复提示符，下一轮仍能发起请求

#### Scenario: 上下文超限展示

- **WHEN** 当前模型调用明确报告上下文超限
- **THEN** 显示上下文超限及显式 /clear 后重新提问的提示，保留记录，不自动清空、摘要、压缩或裁剪，不承诺直接重试相同历史即可恢复

#### Scenario: 取消后清理失败展示

- **WHEN** 用户按 Ctrl+C 后命令返回 failed/cleanup_failed
- **THEN** 终端显示清理失败、原始取消原因和残留进程风险，保留可通过 /evidence 查询的输出与状态；轮次以失败终结后恢复提示符，不自动重试命令

#### Scenario: EOF 关闭时清理失败

- **WHEN** 运行中遇到 EOF，命令有界收尾后返回 cleanup_failed
- **THEN** 关闭前显示清理失败及残留风险，CLI 以失败退出，不显示正常关闭且已清理成功，不启动后续工具或模型请求

#### Scenario: 文本只显示一次

- **WHEN** 同一响应的文本先以增量到达，随后出现在最终结果中
- **THEN** 最终结果不重复打印已展示的文本；没有任何文本增量时展示最终文本
